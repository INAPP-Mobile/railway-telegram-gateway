# Enforce Required Environment Variables at Startup\n\n## Problem\n`GATEWAY_API_KEY` is currently optional — the app silently runs with zero protection on admin endpoints. This creates a security risk.\n\n## Resolution\nUpdate **src/index.ts** startup logic to fail fast when critical variables are missing.\n\n### Required Variables\nFrom .env.example:\n\n| Variable | Default | Must Be Set? |\n|----------|---------|-------------|\n| `GATEWAY_API_KEY` | *(none)* | ✅ Yes |\n| `TELEGRAM_BOT_TOKEN` | — | ⚠️ See below |\n| `BASE_URL` | localhost | Optional |\n| `PORT` | 3000 | Optional |\n\n### Implementation Requirements\n\n1. In `src/index.ts`, after loading env vars, add validation:\n```typescript\nconst required = [\n  'GATEWAY_API_KEY',\n];\n\nfor (const var of required) {\n  const value = process.env[var]?.trim();\n  if (!value) {\n    console.error(`FATAL: ${var} environment variable is required.`);\n    process.exit(1);\n  }\n}\n```\n\n2. Keep current defaults for non-critical vars (PORT, BASE_URL, HEARTBEAT_INTERVAL).\n\n3. Remove the existing `console.warn` fallback — no more degraded mode.\n\n### Acceptance Criteria\n- [ ] App exits with code 1 and clear error message if GATEWAY_API_KEY is not set\n- [ ] Build succeeds (tsc passes)\n- [ ] Deployment starts and verifies env var enforcement\n- [ ] Railway dashboard shows the variable as required (configured in project settings)"
