# Railway Telegram Gateway - Implementation Plan\n\n## Ticket: Initial Project Setup & Core Architecture\n**Assignee**: Coder\n**Priority**: P0 - Blocker\n\n### Goal\nScaffold the project with core webhook → WebSocket routing infrastructure.\n\n---\n\n## 1. Tech Stack Decision\n- **Runtime**: Node.js 22 Alpine Docker image (lightweight)\n- **HTTP Framework**: Hono (ultrafast, modern)\n- **Telegram SDK**: Telegraf v4 (best webhook support via `Telegraf.webhook()`)\n- **WebSocket**: Native `ws` (built-in connection pooling)\n- **State**: In-memory Map for subscriptions (stateless, Railway handles replicas)\n- **Config**: dotenv → Railway env vars\n\n---\n\n## 2. Project Structure\n```\nrailway-telegram-gateway/\n├── src/\n│   ├── index.ts              # App entrypoint: HTTP + WS server bootstrap\n│   ├── app.ts                # Hono app setup, routes, middleware\n│   ├── webhook.ts            # Telegram webhook handler & bot lifecycle\n│   ├── gateway.ts            # WebSocket gateway (connection pool, subscriptions)\n│   ├── admin.ts              # Bot registration API routes\n│   └── types.ts              # Shared TypeScript types\n├── Dockerfile\n├── railway.toml\n├── .env.example\n├── package.json\n└── tsconfig.json\n├── doc/\n│   ├── architecture.md       # Already created\n│   └── implementation-plan.md\n└── README.md\n```\n\n---\n\n## 3. Detailed Module Specs\n\n### 3a. Webhook Handler (`src/webhook.ts`)\n```typescript\n// Receives Telegram updates via Telegraf webhook\nexport class WebhookHandler {\n  private bots: Map<string, Telegraf> = new Map()\n  \n  // Register bot from token and start its webhook\n  registerBot(botId: string, token: string): Promise<void>\n  \n  // Get handler function for Telegraf to use\n  getWebhookHandler(): (update: Update) => Promise<void>\n}\n```\n- Telegraf handles `/webhook/bot/:bot_id` routes\n- Each bot gets its own Telegraf instance\n- All update messages funnel through a single broadcast channel → Gateway\n\n### 3b. WebSocket Gateway (`src/gateway.ts`)\n```typescript\nexport class WebSocketGateway {\n  // Subscribe client to a bot\n  subscribe(ws: WSClient, botId: string): void\n  \n  // Unsubscribe from a bot\n  unsubscribe(ws: WSClient, botId: string): void\n  \n  // Broadcast update to subscribers of a bot\n  dispatchUpdate(botId: string, payload: unknown): void\n  \n  // Handle raw WebSocket messages (subscribe/unsubscribe/health)\n  handleMessage(wsClient: WSClient, message: WSMessage): void\n}\n```\n- Auth: token via query param `?token=<api_key>` or first subscribe msg\n- Each subscription is `(botId, userId)` to isolate access\n- On webhook update → look up all subscribers of that botId → push updates\n\n### 3c. Admin API (`src/admin.ts`)\n```typescript\n// POST /admin/bots (x-api-key header)\n{\n  \"token\": \"<telegram-bot-token>\",\n  \"name\": \"my-bot\"     // optional label\n}\n→ { \"botId\": \"123456:AA...\", \"status\": \"registered\" }\n\n// DELETE /admin/bots/:botId (x-api-key header)\n→ { \"status\": \"unregistered\" }\n\n// GET /admin/bots (x-api-key header)\n→ [{ \"botId\": \"...\", \"userId\": 123, \"status\": \"active\" }]\n```\n- Auto-registers webhook URL with Telegram API on register\n- Validates bot token via `getMe` call\n- Stores bot config in Railway secrets or env-based KV\n\n### 3d. App Setup (`src/app.ts`)\n```typescript\n// HTTP routes:\nconst app = new Hono()\napp.post('/webhook/bot/:botId', webhookHandler)   // Telegram webhooks\napp.post('/admin/bots', admin.registerBot)         // Bot management\napp.delete('/admin/bots/:botId', admin.unregisterBot)\napp.get('/admin/bots', admin.listBots)\n\n// WS upgrade:\nwsGateway.handleUpgrade(app)  // ws://host/?token=<key>\n```\n- Server listens on port from `$PORT` env var (Railway standard)\n- CORS disabled for production, configurable\n\n### 3e. Client SDK (`/client-sdk/`)\nTypeScript client for connecting:\n```typescript\nclass TelegramGatewayClient {\n  constructor(url: string, authToken: string)\n  subscribe(botId: string): Promise<void>\n  unsubscribe(botId: string): Promise<void>\n  onUpdate(callback: (botId: string, update: Update) => void): void\n  close(): void\n}\n```\n- Auto-reconnect with exponential backoff\n- TypeScript typed for Telegram updates\n- Publish to npm as `@railway/telegram-gateway-client` or include in monorepo\n\n---\n\n## 4. Environment Variables (Railway)\n```env\nPORT=3000                        # Server port\nGATEWAY_API_KEY=<key>            # Single API key for admin endpoints\nWEBHOOK_SECRET=<secret>          # Optional: verify webhook authenticity\nSUBSCRIPTION_MAX_PER_CLIENT=10   # Rate limit per WS client\nWEBSOCKET_HEARTBEAT_INTERVAL=30000\n```\n\n---\n\n## 5. Dockerfile (multi-stage)\n```dockerfile\nFROM node:22-alpine AS builder\nWORKDIR /app\nCOPY package*.json tsconfig.json ./\nRUN npm ci\nCOPY . .\nRUN npm run build\n\nFROM node:22-alpine\nWORKDIR /app\nCOPY --from=builder /app/dist ./dist\nCOPY --from=builder /app/node_modules ./node_modules\nCOPY --from=builder /app/package.json ./package.json\nEXPOSE 3000\nCMD [\"node\", \"dist/index.js\"]\n```\n\n---\n\n## 6. Telegram Webhook Registration Flow (on bot register)\n```\n1. Admin POSTs bot token to /api/bots\n2. Service validates via Bot API getMe\n3. Service sends setWebhook API call:\n   PUT https://api.telegram.org/bot<bottoken>/setWebhook\n   {\n     url: `<gateway_host>/webhook/bot/<botId>`,\n     drop_pending_updates: true,\n     allowed_updates: [\"message\", \"channel_post\", \"my_chat_member\"]\n   }\n4. On deregister: deleteWebhook call\n5. Bot webhook URL automatically set - no manual Telegram Dashboard setup needed\n```\n\n---\n\n## 7.
