# Railway Telegram Gateway - Architecture\n\n## Overview\nReceives Telegram webhook updates → routes to connected clients via WebSocket.\n\n## Components\n\n### 1. Webhook Receiver (/webhook/bot/:bot_id)\n- Accepts POST from Telegram Bot API\n- Validates update (signature if enabled)\n- Broadcasts to WS clients subscribed to that bot_id\n\n### 2. WebSocket Gateway (ws://host)\n- Connection management with per-connection auth (token in URL/query)\n- Subscribe/unsubscribe to specific bot updates\n- Update broadcast pipeline: webhook → filter by bot → push to subs\n\n### 3. Client Protocol (WS JSON)\n```\nClient → Server:\n{ \"type\": \"subscribe\", \"botId\": \"<bot_id>\", \"filter\": \"all\" }\n{ \"type\": \"unsubscribe\", \"botId\": \"<bot_id>\" }\n{ \"type\": \"health\" }\n\nServer → Client:\n{ \"type\": \"update\", \"botId\": \"<bot_id>\", \"payload\": <telegram_update> }\n{ \"type\": \"error\", \"message\": \"...\" }\n{ \"type\": \"pong\" }\n```\n\n### 4. Bot Registration (Admin API)\n- POST /api/bots → register bot token + webhook URL (auto-set to this service)\n- Store in env/Railway secrets per bot, or DB for multi-tenant\n- Use Telegraf framework for webhook handling\n\n## Tech Stack\n- Runtime: Node.js 20+ via Docker\n- Framework: Hono (HTTP) + uWebSockets.js\n- Telegram SDK: Telegraf framework for webhook processing\n- Storage: In-memory (stateless, Railway scales)\n- Auth: API key per connection\n- Deploy: Railway direct push\n\n## Data Model\nBotConfig { id, token, userIds[] }\nWSClient { ws, token, subscriptions[] }\n"
