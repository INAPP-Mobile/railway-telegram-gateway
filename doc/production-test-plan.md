# Railway Telegram Gateway - Production Test Plan\n\n## Objective\nValidate the gateway is functioning correctly on Railway after deployment and create reusable production tests.\n\n## Pre-requisites\n- Service deployed to Railway production\n- GATEWAY_API_KEY configured in Railway secrets\n- Valid Telegram bot token for testing\n- WebSocket client available for connection testing\n\n## Test Suite\n### Phase 1: Smoke Tests (Run immediately after deploy)\ncurl -s http://<service-url>/health\n→ Expected: { status: \"healthy\" }\n\ncurl -X POST https://<service-url>/admin/bots \\\n  -H 'Content-Type: application/json' \\\n  -H 'x-api-key: $GATEWAY_API_KEY' \\\n  -d '{\"name\": \"test-bot\", \"token\": \"<valid-tg-token>\"}'\n→ Expected: { status: \"registered\", botId: \"...\" }\n\n### Phase 2: Webhook Integration Test\nUse curl or httpie to confirm Telegram webhook URL is set:\ncurl -s https://api.telegram.org/bot<bottoken>/getWebhookInfo\n\nPhase 3: WebSocket Communication Test\ncurl -N --include \\\n  --no-buffer \\\n  -H 'Connection: Upgrade' \\\n  -H 'Upgrade: websocket' \\\n  -H 'Sec-WebSocket-Key: '+ b64encode(os.urandom(16)) \\\n  -H 'Sec-WebSocket-Version: 13' \\\n  http://<service-url>/ws\n\n### Phase 4: End-to-End Test\ncurl --location http://<host>/api/v1/telegram/webhook/bot/<botId> \\\n  --header 'Content-Type: application/json' \\\n   -d '{\"message\": {\"text\": \"test\", ...}}'\n\nPhase 5: Error Boundary Tests\ncurl -X POST http://<host>/api/v1/telegram/webhook/bot/nonexistent\n→ Expected: 404 (bot not registered)\n```\n\n## Template Structure\n```railway-telegram-gateway/\nrailway.toml        # Railway project config\n.env.example        # Reference env vars\ndockerfile          # Build instructions\ndoc/                # Templates and docs \ntests/            Test scripts\ngithub-templates/   GitHub Actions CI config\n`````\n"
